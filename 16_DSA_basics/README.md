# 16_DSA_Basics

This folder is part of a personal collection of materials created for
**practicing interview coding problems** in Python. Unlike the other
folders in this collection, this one is **explanation-only** — it covers
the conceptual foundations of core data structures without code
implementations, since a solid grasp of *how* and *why* each structure
works is essential before implementing or using it in a problem.

## Contents

| # | Folder | File | Description |
|---|--------|------|-------------|
| 1 | `arrays/` | `arrays.md` | Fixed vs. dynamic arrays, indexing, and operation complexities |
| 2 | `stack/` | `stack.md` | LIFO structure, push/pop/peek, and common use cases |
| 3 | `queue/` | `queue.md` | FIFO structure, enqueue/dequeue, and queue variants |
| 4 | `linked_list/` | `linked_list.md` | Singly/doubly/circular linked lists and array comparisons |
| 5 | `hashing/` | `hashing.md` | Hash functions, collision handling, and hash table operations |

## Format

Each explanation file follows a consistent structure:

1. **What is it?** — a plain-language definition of the data structure.
2. **Key Characteristics** — the defining properties that set it apart.
3. **Core Operations and Time Complexity** — a table of standard
   operations with their Big-O complexity.
4. **Types/Variants** (where applicable) — the different flavors of the
   structure (e.g. singly vs. doubly linked list).
5. **Real-World and Programming Uses** — where the structure shows up in
   practice.
6. **Why It Matters in Interviews** — the kinds of problems it's used to
   test.
7. **Advantages and Disadvantages** — trade-offs versus other
   structures.

No code is included in this folder by design — it's meant to build
conceptual understanding first. Once the concepts here are clear, the
`14_Searching`, `15_Sorting`, and other numbered folders in this
collection provide hands-on, runnable implementations that build on
these foundations.

## Purpose

This folder is meant purely for **interview preparation practice** —
data structure fundamentals are the theoretical backbone behind almost
every interview coding problem, and clearly understanding trade-offs
(e.g. array vs. linked list, or when hashing turns an O(n²) approach
into O(n)) is often more important to interviewers than syntax
familiarity.
